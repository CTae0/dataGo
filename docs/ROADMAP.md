# 어디 살까? — 확장 계획 (생활비 정확도 → 생활 인프라·문화 → 서비스 기능)

## Context
지금 서비스는 전국 시군구 256곳의 주거비·공공요금·장바구니·외식비로 월 생활비를 추정하고, 유머 A/B 질문 15개(생활 9 + 어디서 6)로 추천 카드 3장을 보여 준다.
다음 단계로 **② 생활 인프라, ③ 문화·여가, ④ 생활비 정확도, ⑥ 서비스 기능**을 넓힌다 (정책·혜택, 환경·안전은 이번 범위 밖).
핵심 가치가 '생활비 비교'라서 ④를 먼저 다지고, ②③은 같은 틀(시설 수집 → 시군구 집계 → A/B 질문·카드 사실)로 붙인 뒤, ⑥으로 쓰기 좋게 마무리한다.

## 공통 원칙 (지금까지 하던 방식 유지)
- 전국 단위 원천 우선, 시군별 수작업은 미룬다. 지역 키는 `dim.region_xwalk`로 leaf 256곳에 매핑 (`pipeline/region_xwalk.py`)
- 수집기는 `std_fees.py`·`kca_price.py` 패턴 그대로: 원본 jsonb 보관, 이어받기, `pipeline/quota.py` 호출 예산, Airflow DAG(`dags/eodi_pipeline.py`)
- 집계는 `sql/mart/NN_*.sql` + `eodi_build_mart`, 질문·계수는 `api/cost_model.py`, 카드 문구는 `api/describe.py`
- 출처는 `meta.data_source` + `ATTRIBUTION.md`에 추가하고 화면 하단에 표시
- 새 질문도 유머 A/B + 작은 글씨 기준, 답 하나 = 계수 하나 또는 조건 하나. 테스트(`tests/test_cost_model.py`)에 계수·조건 추가

## 1단계 ④ 생활비 정확도
| 할 일 | 원천 (전국) | 모델 변화 |
|---|---|---|
| 전월세 전환율을 지역별로 | 한국부동산원 R-ONE 전월세전환율 (시도·권역, 월) | `RATE` 상수 → 시도별 값 (`sql/mart/10_rent.sql`, `cost_model._housing`) |
| 관리비 추가 | 공동주택관리정보시스템(K-apt) 단지별 관리비 API | 아파트 거주 비중 반영한 시군구 ㎡당 관리비 중위 → 새 항목 '관리비' |
| 자가용 유류비 | 오피넷(한국석유공사) 시군구 평균 유가 API | 새 A/B 질문 "출퇴근은 내 차로?" + 주행거리 → 새 항목 '기름값' (버스와 둘 중 하나) |
| 전기요금 | 한국전력 주택용 누진 요금표 + 가구 평균 사용량(한전 전력통계) | 전국 공통 요금표 × 가구원 수별 사용량 × 냉방 질문(A/B) → 새 항목 '전기' |
| 상하수도 기본요금 | 표준데이터에 없음 → 행안부 지방공공요금 시도값으로 기본요금 근사 | `20_utility.sql` 보정 |
- 결과: 항목 7개 → 10개 (관리비·기름값·전기). 카드 내역 막대 색은 categorical 8슬롯 안에서 유지 (기름값·버스는 같은 '교통' 묶음)

## 2단계 ② 생활 인프라 + ③ 문화·여가 (같은 틀)
**공통 기반**
- 시군구 인구: 행안부 주민등록 인구(월) → `dim.region_population` (인구 대비 지표의 분모)
- 시설 적재기 `pipeline/poi.py`: 표준데이터·공공 API의 시설을 좌표째 `raw.poi`(종류, 이름, 좌표, 원천)로 → PostGIS로 시군구에 넣기 (주소 매핑 대신 좌표 포함 판정)
- 집계 `sql/mart/60_amenities.sql` → `mart.region_amenities`: 종류별 개수, 인구 1만 명당, 대표점(label_point)에서 가장 가까운 시설까지 거리

**시설 종류와 원천 후보**
| 갈래 | 시설 | 원천 |
|---|---|---|
| ② 의료 | 병원·의원, 약국, 응급실 | 건강보험심사평가원 병원·약국 정보 API, 국립중앙의료원 응급의료기관 |
| ② 육아·교육 | 어린이집, 초·중·고 | 한국보육진흥원 어린이집 정보, 전국초중등학교위치 표준데이터 |
| ② 교통 | 도시철도역, KTX·SRT역 | 전국도시철도역사정보 표준데이터, 철도역 위치(국가철도공단·코레일) |
| ② 녹지 | 도시공원 | 전국도시공원정보 표준데이터 |
| ③ 문화 | 도서관, 공연장, 영화관, 박물관·미술관 | 전국도서관 표준데이터, 공연시설·영화상영관(지방행정 인허가), 박물관·미술관 정보 |
| ③ 여가 | 공공체육시설, 관광지 | 공공체육시설 정보, 전국관광지정보 표준데이터 |

**질문 (A/B, '어디서' 묶음에 추가) 예시**
- "병원은?" A: 아프면 10분 안에 응급실 / B: 튼튼해서 상관없음
- "아이 학교는?" (자녀 있는 가구만) A: 초등학교는 걸어서 / B: 상관없음
- "지하철·KTX는?" A: 역세권은 못 참지 / B: 상관없음
- "주말엔?" A: 도서관·공연장 순례 / B: 집이 최고
- "운동은?" A: 체육관·공원 출석 도장 / B: 숨쉬기 운동
- 조건 방식은 지금 `WHERE`와 같다 (거리·인구당 개수 기준, 너무 엄격하면 앞쪽부터 완화)

**카드**: 사실 칩에 "응급실 6km", "도서관 12곳", "KTX역 15분" 같은 줄 추가, 상세 패널에 시설 표

## 3단계 ⑥ 서비스 기능
- **지역 비교**: 결과·지도에서 2~3곳 골라 항목별 나란히 (같은 막대·표, 차이 강조)
- **월급 대비 여윳돈**: 월 실수령액(선택 입력) → "월 ○○만 원 남아요" 카드 줄 + 저축률 배지
- **결과 공유 이미지**: 카드 3장을 PNG로 저장/공유 (페르소나 문구 포함, 출처 한 줄 포함)
- **공개 배포**: 웹(정적) + API + DB를 한 서버(Docker Compose)로, 공개 전 체크
  - 이용조건 미확인 원천(`molit_rent`, `mois_public_fee`, `mois_dining`) 확인, 출처 표시 점검
  - 운영계정 증량(국토부·소비자원 API), 비밀키는 서버 환경변수, API 캐시(결과는 하루 단위로 같음)

## 진행 순서와 사용자 할 일
1. 1단계 ④ (데이터 원천 4개, 질문 2개 추가)
2. 2단계 공통 기반(인구, `pipeline/poi.py`, `mart.region_amenities`) → ② 의료·교통 → ② 육아·녹지 → ③ 문화·여가
3. 3단계 ⑥: 비교 → 여윳돈 → 공유 이미지 → 배포
- **사용자 할 일(활용신청·키)**: 한국부동산원 R-ONE, K-apt 관리비, 오피넷, 심평원 병원·약국, 표준데이터들(학교·도시철도·공원·도서관·관광지), 행안부 주민등록 인구

## 확인 방법 (단계마다)
- 수집: fetch_log 건수 = 저장 건수, `dim.region_xwalk_unmatched` 0, 시설은 좌표가 시군구 밖인 건수 0
- 집계: 표본 시군구(춘천·강남·양양·제물포구)를 원본에서 손으로 계산한 값과 비교
- 모델: 새 계수·조건마다 테스트 추가 (손계산 일치, 해당 항목만 변함, 너무 엄격한 조건 완화)
- 화면: 브라우저 패널을 연 상태에서 질문 → 카드 → 지도·비교·공유 이미지까지 한 번씩
